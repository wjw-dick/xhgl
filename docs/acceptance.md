### 2.2 单企业与去租户改造（实测通过）

- 后端：管理员登录只接收 `username/password`；用户登录/注册不再接收 `tenantCode`；公开门户、产品、公告、菜单、FAQ、需求、咨询接口不再接收租户参数。
- 响应清理：`AuthUser`、`BaseEntity`、`AuditLog`、`Announcement` 的 `tenantId` 字段不参与 JSON 序列化；登录/分享/门户接口返回 `company` 而非 `tenant`。
- 角色收敛：`TENANT_ADMIN` 改为 `ADMIN`；删除 `SYSTEM`、`ENGINEER`、`CONTRACT`、`FINANCE`、`SERVICE_MANAGER`、`TECHNICIAN`、`SALES` 角色；仅保留管理员与客户。
- 平台端删除：`PlatformController`、`platform_user` 表/实体/Mapper、`/api/platform/**`、PC 平台页面与路由全部移除。
- 企业注册删除：后台 `/register`、`POST /api/public/tenants/register`、`GET /api/public/tenants` 移除；管理员账号由种子数据初始化。
- 数据清理：删除 JSD/YN 演示数据域及全部关联业务数据，数据库当前仅保留 1 个企业数据域；公告来源迁移为 `SYSTEM`/`COMPANY`，通知用户类型迁移为 `ADMIN`。
- 页面清理：admin-web 登录页删除企业编码输入；portal-web、mp-h5、原生小程序删除企业选择/租户编码输入；后台无平台/租户管理菜单。

### 2.3 客户在线报修照片上传（实测通过）

- 客户侧文件接口 `POST /api/customer/files/upload`（JWT 客户身份、企业数据域隔离、每分钟 30 次限流），返回 `FileRecord`，写入 `file_record` 并记录审计日志。
- 报修工单 `POST /api/customer/tickets` 支持 `photos` 字段（逗号分隔 URL），工单详情原样返回，便于售后端查看现场照片。
- 实测：验收临时用户账号登录上传 PNG → 返回 `/uploads/...png` → 创建年检工单并携带该照片 → 工单详情 `photos` 与上传地址一致。
- 存储层路径安全：`category` 仅保留字母/数字/下划线/短横线，扩展名仅接受 `.[a-z0-9]{1,10}`，阻断 `../` 目录穿越。
- 三端入口：portal-web 客户中心「售后服务 → 在线报修」、mp-h5「售后服务 → 在线报修」均可选图上传并显示缩略图；原生小程序报修页实现 `wx.chooseMedia` + `wx.uploadFile`（最多 6 张），真机待验。

### 2.4 自助注册与登录（实测通过）

- 管理员：种子账号 `admin / 123456`，后台登录只填账号密码，不填写企业编码；后台不提供企业注册入口。
- 客户：`POST /api/public/auth/register` 创建客户档案、主联系人（手机号 AES-GCM 加密 + 掩码）与 `CUSTOMER` 账号，注册响应直接返回客户会话；企业/单位名称、所属行业、地区选填，企业名称留空时以联系人姓名建档；门户、mp-h5 注册与重新登录均实测通过。
- 校验实测：重复登录账号 → 409「该登录账号已被使用」；弱密码 `12345678` → 400「密码须同时包含字母和数字」；手机号、用户/客户配额均有服务端校验。
- 登录限流与注册限流：客户注册 5 次/10 分钟/IP；密码 BCrypt 存储。
- Playwright：单企业 UI 验收 9/9 PASS，控制台 0 错误。

### 2.5 后台删除客户注册档案（实测通过）

- 客户档案列表与详情页新增「删除客户」入口，二次确认后调用 `DELETE /api/admin/customers/{id}`。
- 删除时**物理删除**该客户的登录账号、联系人、相关通知与客户档案，释放用户名、企业名称、手机号等唯一约束；删除后可用相同信息重新注册。
- 已关联需求/咨询/报价/合同/工单/设备/证书/回访/转介绍等业务数据时返回 409，提示先处理业务或改为禁用，避免误删业务数据。
- 实测：注册无业务客户 → 后台删除 → 使用同一企业名称、账号、手机号重新注册成功 → 再次删除成功；删除有关联业务客户 #1 → 409；数据库无残留 `deleted=1` 客户/账号/联系人记录；Playwright 删除交互通过，控制台 0 错误。

### 2.6 销售顾问全端移除（实测通过）

- 后端：删除 `SalesController` 与 `/api/admin/sales/*` 接口；移除 `SALES` 角色、`sales` 账号及 `isSales` 数据范围逻辑；相关负责人字段与历史数据统一迁移至管理员。
- PC 后台：报表为「业绩归属（负责人）」，需求分配/转派标签为「负责人」，用户管理默认角色为管理员。
- mp-h5：删除销售工作台/客户需求/报价审批/业绩看板 4 个页面、销售 TabBar、销售登录模式与销售个人中心入口；仅保留客户移动端。
- 原生小程序：删除 4 个销售页面，页面数由 22 调整为 18；登录页/个人中心/协议移除销售视角。

### 2.7 业务记录删除与「待认领」文案（实测通过）

- 后台列表与需求详情新增「删除」入口，二次确认后调用对应 `DELETE` 接口；`公海/公海池` 统一改为 `待认领/待认领池`。
- 需求：删除需求与跟进记录，关联咨询服务置空；存在方案或报价时返回 409，需先删除下游。
- 售前咨询、成功案例：直接物理删除。
- 方案：存在关联报价时返回 409；删除后可再次创建同名方案。
- 报价：删除报价与议价记录；已生成合同时返回 409。
- 合同：级联物理删除订单、收款计划、发票、安装验收、设备、维保计划、满意度与回访；关联工单的设备字段置空，工单保留。
- 售后服务：级联物理删除工单处理记录、满意度与备件领用记录。
- 实测：自动化脚本 8/8 PASS；数据库复核所有测试主键均为 0 行（含 `deleted=1` 残留），合同级联设备/维保/收款计划/订单均无残留，工单删除后处理记录为 0 行；审计日志按模块记录「删除」。回归 `scripts/verify.ps1` 26/26 PASS。
